# Плагин «Кто смотрит?» — выбор профиля CUB при запуске Lampa

Статус: **v1 реализован** (спека 2026-11-20, код 2026-11-24). Репозиторий `lampa-who-watching`, файл
`who-watching.js`; в torrwatch ничего не меняется — доставка установкой плагина ссылкой в «Расширениях» Lampa.
Правки в `torrwatch.exe`, `internal/lampa/serve.go`, конфиг и UI **не планируются** (вариант с инъекцией в
`index.html` отклонён).

Состав репозитория: `who-watching.js` (плагин), `README.md` (установка и ограничения), `SPEC.md` (этот файл),
`LICENSE` (MIT), `test/plugin.test.js` (тесты без зависимостей), `dev/preview.html` (стенд вёрстки без аккаунта и
Premium), `.github/workflows/ci.yml` (синтаксис + тесты). Проверено на Lampa 3.4.8 (`app_digital 348`, коммит
`cebb2b91`).

Имя и оформление: репо `lampa-who-watching`, файл `who-watching.js`, заголовок «Кто смотрит?» / "Who's watching?",
глобальный guard `window.who_watching_ready`. Лицензия плагина — MIT (Lampa — GPL-2.0, плагин работает через
публичный API и не является производной работой; при публикации упомянуть).

## 1. Задача

Сейчас профиль в Lampa переключается только вручную: иконка профиля в «шапке» (`.head .open--profile`) или
«Настройки → аккаунт → Профиль». При запуске Lampa молча берёт сохранённый профиль, а если его нет — основной.
Нужно: **при каждом запуске** Lampa сразу показывать выбор профиля CUB, чтобы не делать лишних нажатий (семейный
сценарий: взрослый/детский профили).

Профили — **нативные CUB** (`Account.Profile`), а не локальные профили плагина «Профили» (levende/lampa-plugins).
С плагином levende не конфликтуем и не интегрируемся, в README — упоминание.

## 2. Принятые решения (2026-11-20, пользователь)

## 3. Изученная база: Lampa 3.4.8 (коммит `cebb2b91`, сборка 2026-11-23)

Локальная копия: `C:\ProgramData\TorrWatch\Lampa\versions\cebb2b91bbf8\` (`app.min.js` 2,4 МБ, `css/app.css`,
`lang/ru.js`). Якоря сверены и на 3.4.7 (`a4a8e0fe`), и на 3.4.8: `Account.Profile`, `select$3`, `fullsize`,
`selectbox_icon`, `title_out_confirm`, `backward`, `updatePluginDB`, `addPluginParams` — на месте. Ниже — точные
ориентиры, по ним перепроверять после обновлений Lampa.

### 3.1. Профили CUB

- `Account.Profile = { init, update, check, select, icon }`; `select` — документированный вызов
  (старый алиас `Account.showProfiles()` жив, пишет `console.warn('… use Account.Profile.select()')`).
- `Profile.select(cb)` (внутри `select$3`): `ParentalControl.personal('account_profiles', …)` → если нет
  `Permit.token` — `Modal.account()` (окно входа); затем `Api.load('profiles/all')`; лимит профилей
  `hasPremium() ? 8 : 3`; элементы: `[«Добавить профиль»].concat(profiles.reverse())`; `Select.show({ title:
  Lang.translate('account_profiles'), items, onSelect, onBack: callback, onFullDraw: container => container.append(
  <div class="selectbox__text selector">account_profile_info</div>) })`.
- `onSelect`: `account.profile = a.clone; Storage.set('account', account); callback(); Listener$1.send('profile_select',
  { profile })` — это шина **`Lampa.Account.listener`**, не глобальная `Lampa.Listener`.
- `Profile.check` в `Account.init()` при старте: если `account.profile.id` нет — молча выбирает профиль `main` и
  пишет в `Storage`. Именно это и обходим гейтом (сам `check` не трогаем).
- `profiles/all` → `{ secuses, profiles: [{ id, name, icon, main, child, age }] }`; иконки
  `<cub_domain>/img/profiles/<icon>.png`.

### 3.2. `Select.show` — параметры и разметка

JSDoc самого Lampa: `title`, **`fullsize`** («использовать весь экран»), `items`, `nomark`, `nohide`, `onSelect`,
`onBack`, `onFullDraw`. Класс `.selectbox--fullsize .selectbox__content { width: 100% }`.

Шаблон `selectbox`:
`.selectbox > .selectbox__layer + .selectbox__content.layer--height > .selectbox__head > .selectbox__title` и
`.selectbox__body`.

Элемент `selectbox_icon`: `.selectbox-item.selectbox-item--icon.selector` с `.selectbox-item__icon` (внутри
`img.size-medium`), `.selectbox-item__title`, `.selectbox-item__subtitle`.

CSS, которое придётся аккуратно переопределять только под нашим маркером:

| Селектор | Что в родном CSS |
|---|---|
| `.selectbox__content` | `position: fixed; left: 100%; width: 35%; background: #262829; transition: transform .2s` |
| `.selectbox-item` | `padding: 1.5em 2em; position: relative; will-change: transform` |
| `.selectbox-item--icon` | `display: flex; align-items: center` |
| `.selectbox-item.focus` | `background-color: #353535` |
| `.selectbox-item.selected::after` | чекмарк `absolute; top: 50%; right: 2em` |
| `.selectbox-item__title / __subtitle` | `1.3em` / `1.1em`, opacity .7 |
| `.selectbox__text` | пояснение, `padding: 1.5em 2em` |

- Фокус при открытии: `Select.show` ставит `focus_index = -1`, затем `Controller.collectionFocus(false, panel)` —
  фокус на **первом** `.selector` панели. В нативном порядке это «Добавить профиль» (он первый в массиве). После
  реверса первым станет первый профиль — это и нужно.
- Прокрутка панели — вертикальный `Scroll` (`scroll$5`): свои высоты и маски; для горизонтали его надо
  нейтрализовать только внутри маркера.

### 3.3. Плагины и жизненный цикл

- Плагины грузятся самим `app.min.js` в очереди загрузки **до** `startApp()`: `Plugins.task` собирает список
  (`Account.Api.plugins` + `Storage 'plugins'` + `./plugins/modification.js`), `Plugins.load(call)` инжектит через
  `Utils.putScriptAsync` и вызывает `call()` (→ `showApp` → `startApp`). Значит подписка на `app ready` успевает.
- События: `Lampa.Listener.send('app', {type:'start'})` — в начале `startApp` (модули не готовы);
  `{type:'ready'}` — после `Render.app()` и `Layer.update()`, `window.appready = true`.
- `Activity.refresh()` — публичный: через 1 с вызывает `activity.refresh()` → `Activity.replace()`. Смену профиля
  главная сама не перерисовывает (на `profile_select` реагируют только закладки/история).
- `Lampa.Manifest.app_digital` (348 для 3.4.8) — для guard'а версии.
- `window.Lampa` содержит `Account`, `Select`, `Controller`, `Activity`, `Storage`, `Lang`, `Template`, `Layer`,
  `ParentalControl`, `SettingsApi`, `Manifest`, `Color`, `Loading`, `Noty` (`initClass()` — в конце `app.min.js`).
- **`Lampa.App` не экспортирован** — `App.close()` из родного кода выхода недоступен плагину.

### 3.4. Родное поведение «Назад» (его и переиспользуем)

`Activity` при `backward` с `count == 1`, `!Platform.is('browser') && !Platform.desktop()` и позже 2 с после
старта показывает:

```js
Select.show({ title: Lang.translate('title_out'),
  items: [{ title: Lang.translate('title_out_confirm'), out: true }, { title: Lang.translate('cancel') }],
  onSelect: a => { if (a.out) { out(); Controller.toggle(enabled); App.close(); } else Controller.toggle(enabled); } })
```

`title_out` = «Выход», `title_out_confirm` = «Да, выйти». На браузере/десктопе окна нет вовсе — это штатно.

## 4. Поведение плагина (целевое)

### 4.1. Когда срабатывает

На `app ready` (плюс страховка `if (window.appready)`), с задержкой ~300 мс (клавиатура включается через 1 с,
`Select`/`Layer` к этому моменту готовы). Гейт показывается, только если все условия:

1. `Lampa.Account.Permit.token` есть (залогинен);
2. `window.lampa_settings.account_use` не выключен;
3. предпроверка `Lampa.Account.Api.load('profiles/all')` вернула `profiles.length >= 2` (результат кэшировать в
   памяти на загрузку страницы; при ошибке — гейт не показывать);
4. в этом запуске гейт ещё не показывали (обычная переменная модуля, **не** `sessionStorage` — гейт нужен каждый
   запуск, а не «раз в сессию вкладки»).

Иначе — тишина, Lampa стартует как обычно.

### 4.2. Экран

Полноэкранная родная панель: `Select.show` нашего вызова с `fullsize: true`. Заголовок родной — «Профили».
Горизонтальный ряд плиток по центру: аватар (крупный), имя, родная подпись (`.selectbox-item__subtitle`:
«основной» / «детский (до 12)»), выбранный отмечен родным чекмарком в углу плитки, «+» — последняя плитка
(родной `ghost`, если лимит достигнут). Ниже — родное пояснение `account_profile_info`. Фон `#262829`, фокус
родной `#353535` + `transform: scale(1.05)` (никаких новых цветов/шрифтов/иконок).

Прокрутка: `overflow-x: auto`, скроллбар скрыт, `scrollLeft` подтягивается по `hover:focus`, маски по краям
включаются только при `scrollWidth > clientWidth`; пересчёт на `Lampa.Listener` `resize_end`. Второй ряд не
делаем: 3 профиля (бесплатный CUB) влезают всегда.

### 4.3. «Назад»

- В нашем вызове подменяем `onBack`: панель закрывается родным путём, затем `setTimeout(0)` → `Controller.back()`,
  то есть нажатие отдаётся родному обработчику `backward`: на ТВ появится родное «Выход / Да, выйти / Отмена»;
  на браузере — как без плагина.
- Если в окне выхода выбрали «Отмена» — гейт открывается снова (нельзя остаться в приложении под прошлым
  профилем в обход). Ловится в обёртке `Select.show`: у окна выхода есть пункт `out: true`.
- «Да, выйти» — выходит родной код (`out()` + `App.close()`), мы его не переписываем.

### 4.4. После выбора профиля

Слушаем `Lampa.Account.listener.follow('profile_select', …)` → через ~200 мс `Lampa.Activity.refresh()`, чтобы
главная пересобралась под новый профиль. Если на ТВ это будет заметно дёргаться — резервный вариант:
`location.reload()` + одноразовая метка-время (защита от цикла), решение локальное.

## 5. Реализация (один файл)

`who-watching.js`, IIFE, без зависимостей, в начале guard:

```js
if (!window.who_watching_ready) startWhoWatching();
```

Каркас (черновик, не финальный код):

```js
function startWhoWatching() {
  window.who_watching_ready = true;
  var gate = { active: false, timer: 0, profiles: null, panel: null };

  var show = Lampa.Select.show;
  Lampa.Select.show = function (object) {
    var ours = gate.pending && object && !!(object.items || []).length &&
               (object.items.some(function (i) { return /\/img\/profiles\//.test(i.icon || ''); }));
    if (ours) {
      gate.pending = false;
      object.fullsize = true;
      object.items = object.items.slice().reverse();        // профили естественно, «+» в конце
      var onFullDraw = object.onFullDraw;
      object.onFullDraw = function (scroll) {
        if (onFullDraw) onFullDraw(scroll);
        var panel = $('.selectbox').last().addClass('who-watching');
        gate.panel = panel;
        setFocusFollow(panel);                              // горизонтальная прокрутка
      };
      var onBack = object.onBack;
      object.onBack = function () { if (onBack) onBack.apply(this, arguments); backToNative(); };
    }
    return show.apply(this, arguments);
  };
}
```

Полный набор работ — в §8. Обязательные правила:

- Всё в `try/catch`; любая ошибка → родной вертикальный вид (деградация), в консоль — одна строка.
- Проверка `Lampa.Manifest.app_digital >= 348` (иначе не лезем).
- Маркер `gate.pending` ставится непосредственно перед `Lampa.Account.Profile.select()`; `Profile.select` асинхронен
  (сначала `profiles/all`), поэтому флаг живёт до закрытия панели: сброс на `Lampa.Select.listener.follow('close')`
  и страховочный таймаут 10 с.
- Дополнительная проверка содержимого (`/img/profiles/`) — чтобы никогда не перекрасить чужой селект.
- Никаких сетевых запросов, кроме предпроверки `profiles/all` (и той, что делает сам `Profile.select`).
- Никаких правок поведения для селектов, открытых из шапки/настроек: маркер не выставлен — обёртка ничего не делает.

## 6. Известные ограничения (в README)

- Только CUB-профили и только залогиненный аккаунт; с плагином «Профили» (levende) не интегрируемся.
- PIN родительского контроля спрашивается как в родном приложении, то есть при каждом запуске, если включён.
- «Добавить профиль» — родное; после создания список не перерисовывается (родная особенность) — профиль
  появится при следующем открытии.
- DOM `.selectbox` — не публичный API Lampa: после её обновления возможен откат к родному виду (плагин при этом
  не ломает приложение). Проверено на 3.4.8; после обновлений — один ручной прогон.
- Отключение — удалить ссылку в «Расширениях».

## 10. Доставка, доступность и «плагин не отвечает по 400»

Lampa **не устанавливает** плагин, а загружает его при каждом запуске: `Plugins.task` собирает список
(`Account.Api.plugins` + `localStorage 'plugins'` + `./plugins/modification.js`), `Plugins.load` инжектит каждый URL
через `Utils.putScriptAsync`. В `addPluginParams` к каждому URL добавляются `email`, `logged`, **`reset=<Math.random()>`**
и `origin` — то есть кэш браузера обходится, и каждый старт Lampa — это новый GET файла плагина.

- Таймаут на скрипт — 60 с. Ошибка (400/404/блокировка/таймаут) → скрипт пропускается, Lampa стартует **без**
  свежего плагина и показывает Noty «При загрузке приложения, часть плагинов не удалось загрузить»
  (`plugins_no_loaded`). Приложение при этом не ломается.
- **Кэш кода в IndexedDB (важное уточнение).** После успешной загрузки `updatePluginDB` дёргает тот же URL с
  `?cache=true` и кладёт исходник в `Cache` (хранилище `plugins`, ключ — чистый URL без параметров). Если при
  следующем запуске скрипт не загрузился, `createPluginDB` выполняет **последнюю удачную копию из кэша**. Итог:
  гейт продолжает работать, даже если хостинг лёг или отдаёт 400; обновления приходят при следующей удачной загрузке.
  Ограничения: кэш живёт в браузере/приложении конкретного телевизора и пропадает при очистке данных или
  переустановке; при самой первой установке без сети кэшировать нечего — плагина не будет.
- Пока репозиторий и страница доступны — обновления и первая установка работают; при недоступности — только кэш
  (у тех, кто ставил раньше). Удаление репо или отключение Pages = новые пользователи плагин не получат никогда,
  старые проживут на кэше до очистки данных.
- Рекомендации по хостингу: основной адрес — GitHub Pages (`https://<user>.github.io/lampa-who-watching/who-watching.js`),
  зеркало/пин — jsDelivr (`https://cdn.jsdelivr.net/gh/<user>/lampa-who-watching@v1.0.0/who-watching.js`,
  тег делает версию неизменяемой). Не использовать `raw.githubusercontent.com` (rate limit, блокировки, 400) и не
  попадать в чёрный список Lampa (`t.me`, `4pda`, `tinyurl`, `lipp.xyz`, `llpp.xyz`, `scabrum.github.io`,
  `bylampa.github.io`, `teletype.in` и т. п. — он вшит в `Plugins.task`).
- Файл ~10 КБ, запросов наружу у плагина нет — трафик и задержка пренебрежимы.
- Резерв: можно добавить в «Расширения» обе ссылки (Pages + jsDelivr) — guard `window.who_watching_ready` делает
  второй запуск no-op; минус — два пункта в списке плагинов. В README описать как опцию.
- Нет сети: при наличии кэша гейт работает на последней удачной версии, без кэша — Lampa открывается как обычно.
  Это осознанное поведение (Lampa должна открываться всегда). В README: «если плагин перестал отвечать — проверьте
  ссылку, при необходимости форкните репо и замените URL».

## 11. Права в публичном репозитории

- Публичный репо **не** означает открытые коммиты: писать в ветки могут владелец и приглашённые (Settings →
  Collaborators → Write; в организации — команды), остальные — только форк + PR (плюс issues/discussions).
- Личный PAT — это полный доступ к твоему аккаунту, и коммиты от твоего имени; передавать его другим нельзя.
  Для людей — инвайт коллаборатора (у них свои аккаунты и ключи), для CI — deploy key или GitHub App.
- Branch protection на `main` (PR + review + опционально проверки) не даёт пушить напрямую даже коллабораторам;
  Pages публикует из ветки, значит в эфир (то, что скачивают телевизоры) попадает только смёрженное.
- Релизы/теги (`v1.0.0`, …) + пин на тег через jsDelivr = неизменяемая версия для тех, кому не нужен «latest».
- Если проект забросить: MIT-лицензия и раздел README «как форкнуть и заменить URL» — фича продолжает жить.

## 12. Справка: как плагины попадают в «магазины»

Три пути установки, все видны в коде Lampa 3.4.8:

1. **Вручную по URL** — «Расширения → Добавить плагин» (`plugins_rules` + согласие `agree_installation`):
   URL кладётся в `Storage 'plugins'` как `{ url, status }`, скрипт инжектится сразу, применяется после
   перезагрузки (`settings_plugins_notice`). Это единственный путь, не зависящий ни от кого, — он и нужен нам.
2. **Из аккаунта CUB** — `Account.Api.plugins` → `GET /api/plugins/all` с токеном (таймаут 3 с, кэш
   `account_plugins`). Список живёт на сервере CUB и привязан к аккаунту: пользователь включает/выключает
   плагины в кабинете, Lampa подтягивает их как «Установленные из CUB» на всех своих устройствах.
3. **Магазин расширений** — `CUB.extensions` → `GET /api/extensions/list` с токеном и профилем (таймаут 5 с, кэш
   `account_extensions`), включается `lampa_settings.plugins_store` (по умолчанию `true`). Витрина серверная и
   курируемая: категории (`extensions_hpu_best/recomend/theme/screensaver/video/control/other`), метки
   «Рабочий» / «Не подтверждён», цены (`extensions_price_free/shareware/paid`), счётчики установок. В статической
   сборке есть даже шаблон экрана-каталога `plugins_catalog` («Рабочие плагины», «Популярные плагины среди
   пользователей») с предупреждением «Установка из неизвестных источников может привести к некорректной работе
   приложения», но кода, который его наполняет, в статике нет — вероятно, он живёт в Android-приложении или
   приходит с сервера.

**Как попасть в официальный магазин:** это не публикация из приложения и не GitHub — это серверная витрина CUB.
Плагин должен попасть в их базу: договорённость с CUB (кабинет/поддержка/Telegram), они проверяют
работоспособность (отсюда метки «Рабочий»/«Не подтверждён»), относят к категории и ставят цену. В Lampa пушить
ничего не нужно — она просто читает `/api/extensions/list`.

**«Пиратские» магазины** — это не механизм Lampa, а сторонние каталоги ссылок (сайты вроде lampaguide, репозитории
наподобие `igorek1986/lampa-plugins`, Telegram-каналы, ветки на 4pda). Установка всё равно ручная по URL; иногда
каталог сам является плагином и подключает выбранное программно через `Lampa.Plugins.add(...)` (модуль `Plugins`
экспортирован в `window.Lampa`), после чего просит перезагрузить приложение.

**Почему экосистема так осторожна.** Плагин — это произвольный JS в контексте Lampa: без песочницы, с доступом к
`localStorage` и токену CUB (`Account.Permit.token`), закладкам и истории; он же может подключать другие плагины.
Отсюда три эшелона защиты: вшитый в `Plugins.task` список хостов/подстрок (`t.me/`, `4pda.`, `tinyurl`,
`lipp.xyz`, `llpp.xyz`, `scabrum.github.io`, `bylampa.github.io`, `teletype.in`), серверный
`/api/plugins/blacklist` (кэш `plugins_blacklist`) и локальный `./plugins/black_list.json`; плюс модалка правил
перед установкой и предупреждения в витрине. Это фильтры от явного мусора, а не изоляция — доверие к автору
плагина остаётся на пользователе.

**Что это значит для нас:** магазин не нужен и не планируется; README прямо говорит «плагин не из магазина,
ставится по ссылке, код открыт — можно прочитать». Попадание в витрину CUB — их решение и их модерация, вне
нашего контроля; если когда-нибудь захочется — сначала стабильный URL, README и рабочая версия, потом разговор.

## 13. Как продолжить (для следующего чата)

1. Открыть локальную копию Lampa: `C:\ProgramData\TorrWatch\Lampa\versions\<коммит>\app.min.js` (актуальный
   коммит — `current.json`). Сверить якоря grep'ом: `Account.Profile`, `select\$3`, `fullsize`, `selectbox_icon`,
   `selectbox-item.focus`, `title_out_confirm`, `backward`, `Plugins.load`.
2. Создать репо `lampa-who-watching` (или папку и инициализировать), перенести туда этот файл как `SPEC.md`.
3. Идти по чеклисту §8; стенд §7 делать до ручных прогонов на ТВ.
4. Если Lampa сменила версию и якоря не совпали — сначала обновить §3, потом код; спека должна оставаться
   актуальной.
5. Всё, что меняется в решениях по ходу, — фиксировать в §2 (дата, формулировка, причина).
